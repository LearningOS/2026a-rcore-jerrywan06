# Lab2：地址空间

## 实现总结

实现匿名内存映射与解除映射，检查页对齐、权限、地址合法性、重叠和物理内存容量，支持向上取整、部分解除与跨区域解除，并回收物理页。重写 `get_time`，逐页校验后向用户空间写回时间，支持跨页结构体。重写 `trace`，按用户页表检查读写权限，拒绝未映射和内核专用地址；迁移上一章按任务独立保存的系统调用计数。

## 实现说明

- `translated_user_buffer` 检查地址加法溢出、Sv39 规范地址、页表项有效位、用户可见位及读写权限。先检查整个缓冲区，再由调用方写入，避免跨页失败时仅写入前半部分。
- 页表翻译只返回有效叶级页表项，解除映射后不会将无效项中的物理页号零误当成合法地址。
- `sys_get_time` 将秒和微秒分别编码为本机字节序，按每页剩余空间写回，不将用户虚拟地址直接当作内核指针，也不要求结构体按页或按机器字对齐。
- `sys_trace` 复用检查后的用户缓冲区读取或写入一个字节，写入截取低 8 位。查询系统调用次数时使用当前任务的计数，统一分发入口在执行调用之前计数。
- `mmap` 将 `prot` 的低三位左移一位转换为 `MapPermission`，额外设置 `U`。不自动给仅写页面增加 `R`，保留教材中 RISC-V 对 `R=0,W=1` 组合的硬件行为。错误权限、非对齐地址、非规范地址、区间溢出、映射重叠与物理页不足返回 `-1`。合法的零长度请求返回 `0`。
- `munmap` 预先检查全部目标页的存在性与用户属性，再解除映射并释放对应的 `FrameTracker`。根据解除区间的位置保留原区域的左段、右段，或拆成两段，因此能够解除区域内部的部分页，也能跨越多个相邻区域。
- 匿名映射分配失败时回滚已建立的数据页映射并释放其物理页。已有页表中间节点随地址空间保持存活，未实现中间页表节点的即时回收。用户页表在返回用户态时由既有 `__restore` 切换并执行 `sfence.vma`，使新的映射状态生效。
- 扩展堆前检查目标页是否已映射，使 `sbrk` 与匿名映射冲突时返回失败。

## 问答题

### 1. Sv39 页表项的组成与标志位

Sv39 的虚拟地址低 39 位由三个各 9 位的虚拟页号索引和 12 位页内偏移组成，高位必须等于第 38 位的符号扩展。页表项为 64 位：`[53:10]` 保存 44 位物理页号，`[9:8]` 是软件保留位 RSW，`[7:0]` 为标志位。基础 Sv39 中高位保留；扩展规范可赋予部分高位其他用途，本实验不启用这些扩展。

| 标志 | 含义 |
| --- | --- |
| `V` | 页表项有效；为 0 时地址翻译失败 |
| `R` | 允许读取 |
| `W` | 允许写入；`R=0,W=1` 是保留的非法组合 |
| `X` | 允许执行；非叶项应使 R/W/X 都为 0 |
| `U` | 允许用户态访问，还需满足相应的 R/W/X 权限 |
| `G` | 全局映射，涉及地址空间标识与 TLB 刷新的处理 |
| `A` | 页面已被访问 |
| `D` | 页面已被写入 |

基础页大小为 4 KiB；更高层的叶项可表示 2 MiB 或 1 GiB 大页，但物理地址必须满足相应对齐。本实验使用三级页表和 4 KiB 叶页。

### 2. 缺页、惰性分配与换页

**异常与寄存器。** 取指、读数据、写数据或 AMO 分别可能产生 Instruction Page Fault、Load Page Fault、Store/AMO Page Fault，异常码分别为 `12`、`13`、`15`。权限不满足、非法页表项或非规范地址也可能产生这些异常，不能仅据异常码判断一定是尚未分配物理页。`scause` 记录异常种类，`stval` 记录导致异常的虚拟地址，`sepc` 保存需要重试或终止的指令地址，`sstatus` 记录原特权级和中断状态，`satp` 提供页表根与翻译模式。这是同步异常，不是通常所说的外部中断。

**Lazy 策略的收益。** 推迟没有实际访问的代码或数据页加载，可以减少初始磁盘 I/O、物理内存占用与页表构建工作，缩短启动时间。只使用申请区间中一小部分时，节省尤其明显。

**10 GiB 的页表开销。** 采用 4 KiB 页需要 `10 × 2^30 / 4096 = 2,621,440` 个叶项。每个页表页容纳 512 项，因此约需 5,120 个底层页表页，共 20 MiB；再加约 10 个中间页表页和一个根页，约 44 KiB。对齐和地址分布可能增加少量节点，数量级仍约 20 MiB，不包含被映射的数据页。使用大页时开销会不同。

**Lazy 策略的实现思路。** `mmap` 先记录地址范围、权限和后备对象，不立即分配数据页。缺页处理器根据 `stval` 查找该区域，确认访问类型与权限，分配并清零物理页，或从文件/交换区读入内容，再建立页表映射、刷新相应 TLB，保持 `sepc` 不变以重试原指令。非法地址、权限错误或无法分配时结束任务；不能将所有缺页都当成可以补页。

**Swap 的页表表现。** 换出时通常清除 PTE 的 `V` 位，使硬件无法继续使用旧物理页号；交换槽位置等信息由软件保留位与内核元数据记录，不能把磁盘位置当成有效物理页号交给 MMU。修改后还需使缓存的旧翻译失效。再次访问时依据后备信息换入并恢复有效映射。

### 3. 用户与内核共用页表及隔离页表

**共用页表时如何更换。** 一个进程在用户态和内核态使用同一个页表根，在两者之间切换特权级通常不需要写 `satp`。切换到不同进程的地址空间时，再由内核写入新的 `satp`；本实验风格的实现还会执行 `sfence.vma`。支持 ASID 时可按标识与映射变更情况减少不必要的全量刷新。

**如何防止用户访问内核页。** 内核映射清除 PTE 的 `U` 位，用户映射设置 `U` 并按需授予 R/W/X。即使用户知道内核虚拟地址，U 态也不能合法访问 `U=0` 的页面；映射代码、只读数据和可写数据时还应分别收紧权限。异常返回相关的页表和上下文同样不能允许用户修改。

**共用页表的优势。** 可以省去系统调用与中断进出时的页表根切换，减少 TLB 刷新成本；内核访问用户缓冲区更直接，且不必依靠专门的共享跳板页维持切换过程中的代码映射。不过仍要校验用户指针并处理权限，不意味着任意用户地址都可安全解引用。

**本章切换页表的时机。** 双页表下，`__alltraps` 先在用户页表下保存上下文，随后写入内核 `satp`；`__restore` 写入当前任务的用户 `satp` 后恢复上下文，两处都执行 `sfence.vma`。如果改用每进程一张、包含受保护内核映射的页表，可在同一进程的用户/内核切换时保持页表根，在调度到不同地址空间时切换。页表隔离可以缓解特定的推测执行侧信道风险，不代表能防范所有侧信道攻击。
