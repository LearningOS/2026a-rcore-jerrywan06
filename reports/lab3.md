## 实现说明

### 直接创建子进程

`sys_spawn` 按用户页表读取以 NUL 结尾的程序名，检查规范地址、用户可读权限、UTF-8 和长度上限；程序名最多读取一页大小的字节。无效指针、不完整或非法字符串、没有对应 ELF 的程序名均返回 `-1`。

成功查找程序后，`TaskControlBlock::spawn` 调用 `new` 为目标 ELF 建立全新的地址空间、PID、内核栈和陷入上下文。随后设置子进程的弱父引用，将子进程加入父进程的 `children`，最后加入就绪队列并返回 PID。该路径没有调用 `fork` 或 `exec`，不复制父进程的数据页。

子进程退出、成为僵尸、被 `wait/waitpid` 回收，以及父进程先退出时的托孤，复用本章已有的生命周期管理。

### 优先级与调度

- 所有新进程初始优先级为 `16`、初始 Stride 为 `0`；直接创建和 `fork` 两条路径都初始化这些字段。
- `set_priority` 接受 `2..=isize::MAX`，成功保存并返回原参数；小于 `2` 时返回 `-1` 且不修改优先级。
- 每次 `fetch` 线性扫描就绪队列，选择 Stride 最小者；相等时保持队列先后顺序。
- 常量 `BIG_STRIDE = 2^63`，本次调度的步长为 `BIG_STRIDE / priority`。即使优先级为 `isize::MAX`，步长仍不为零。
- 取出选中进程后，从其余就绪进程的 Stride 统一减去本次最小值，选中进程的相对 Stride 设为自己的步长。这相当于统一移动计数原点，保持相对次序。由优先级下界可知步长至多 `BIG_STRIDE / 2`，所以计数始终有界，不会因累计值回绕而反转调度顺序。
- `exec` 更换程序但仍属于同一个进程，因此保留调度状态；同时重置新地址空间的堆底和 program break，避免使用旧程序的堆元数据。

## 问答题：Stride 的溢出与比较

### 1. 直接比较回绕后的数值会选择谁

8 位无符号整数中，`p2` 从 `250` 加 `10` 后回绕为 `4`。普通整数比较认为 `4 < 255`，所以下一次仍选 `p2`，不是应当运行的 `p1`。问题在于数值回绕后，整数大小不再等同于累计运行长度的先后关系。

### 2. 为什么差值不超过 BigStride / 2

所有进程从相同的零值开始，初始最大值与最小值差为零。设当前最小值为 `S`，所有进程都在 `[S, S + BigStride/2]` 内。算法只增加最小值对应进程的 Stride，因为优先级至少为 `2`，增加的步长至多为 `BigStride/2`。因此这次更新后所有值仍在原区间内；新的最小值不会变小，所以差值仍不超过该上界。这个归纳说明针对固定就绪进程集合；动态创建进程时还需要明确新进程相对于当前计数原点的初值。

本实现每次调度都移动原点，将就绪进程的相对值控制在 `[0, BigStride/2]`，新进程从相对零值加入，因此不依赖机器整数自然回绕。

### 3. 考虑回绕的比较器

如果两个真实累计值的差严格小于机器整数模数的一半，可用回绕减法判断先后。下面补全 `BinaryHeap<Stride>` 使用的比较函数。Rust 的 `BinaryHeap` 默认弹出最大元素，为弹出真实累计值最小者，最后反转自然顺序：

```rust
impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        let natural = if self.0 == other.0 {
            Ordering::Equal
        } else if self.0.wrapping_sub(other.0) < (1u64 << 63) {
            Ordering::Greater
        } else {
            Ordering::Less
        };
        Some(natural.reverse())
    }
}
```

题目 TIPS 中的 `<` 表示未反转的自然环形顺序：8 位模型下，`125 - 255` 回绕为 `126 < 128`，所以 `125` 实际在 `255` 之后；`129 - 255` 回绕为 `130 > 128`，所以 `129` 在 `255` 之前。若希望类型自身的 `<` 直接满足这些 TIPS，应返回 `natural`，再使用 `BinaryHeap<Reverse<Stride>>` 取最小值。堆优先顺序与自然顺序不能混用。真实堆实现还应让 `Eq`、`PartialEq`、`Ord` 与比较规则保持一致；本次代码采用线性扫描及计数原点平移，不需要自定义堆比较器。
