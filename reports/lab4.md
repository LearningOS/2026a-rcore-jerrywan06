## 实现说明

### 硬链接与 inode 生命周期

- `easy-fs` 的磁盘 inode 与目录项格式保持原有布局。硬链接只增加指向同一 inode 编号的目录项，不复制文件数据；链接数量由根目录中有效引用的数量计算，因此重新打开文件系统后仍能得到正确值。
- 同名链接、源文件不存在、目标已存在、非法文件名均返回失败。当前 easy-fs 仍是根目录下的平面命名空间，文件名最多 27 字节，不接受空名称、嵌入 NUL、路径分隔符、`.` 或 `..`。
- 删除名称时，将目录项置空；查找和列目录忽略空项，创建文件和硬链接优先复用空项，避免重复创建删除导致目录持续增长。
- 文件系统在内存中以弱引用缓存各 inode 的共享句柄，使不同打开路径和硬链接获取的句柄指向同一 `Arc<Inode>`。缓存不额外延长 inode 生命周期。
- 最后一个目录链接消失时，没有活动句柄则立即回收；仍有打开句柄则继续允许读写，`fstat` 返回 `nlink=0`，待最后一个句柄释放后再回收。回收通过既有 `clear_size` 释放直接数据块、一级和二级间接索引相关块，并清除 inode 位图，使 inode 编号可再次分配。
- `Inode::new` 限制为库内部使用，文件句柄统一通过目录查找或创建进入缓存。缓存清理核对句柄地址，防止并发查找替换弱引用后，旧句柄析构错误删除新缓存项。
- 本章未增加日志事务；断电时多块更新的一致性不属于本次必做实现。

### 系统调用与进程兼容

`File` 接口增加状态查询。普通文件返回设备号 `0`、实际 inode 编号、文件类型及当前硬链接数；控制台流返回 `NULL` 类型与零 inode 编号。`fstat` 检查文件描述符及完整用户输出范围，逐页写回 80 字节 C 布局数据，保留字段清零，支持跨页及非对齐指针，失败时不部分写入。

`linkat/unlinkat` 按用户页表读取有界的 NUL 结尾 UTF-8 名称，拒绝无效地址。`open` 同样检查名称与标志；文件读写检查相应用户缓冲区的读写权限。

迁移第四、五章的内存映射、跨页时间写回、优先级和 Stride 调度。`spawn` 从 easy-fs 读取 ELF，直接创建新地址空间，并继承父进程的文件描述符表，已打开文件的偏移通过共享文件描述对象继承；不复制父进程地址空间。`exec` 使用磁盘中的程序替换当前映像，更新堆元数据并保留打开的文件描述符。`spawn/exec` 拒绝不能被 ELF 解析器识别的普通数据文件。

## 第六章问答

### Root inode 的作用与损坏后果

本实现的 root inode 是编号 `0` 的目录 inode，文件系统格式化时预先分配。其数据部分是一组目录项，提供名称到 inode 编号的映射；其大小、直接和间接块指针决定根目录内容存储在哪里。打开程序、创建文件、建立硬链接、删除名称和列出文件都依赖它。

root inode 不保存所有普通文件的数据，而是通向这些文件的命名入口。若它的大小或块指针损坏，遍历可能找不到文件、读取错误目录块，甚至引起越界或内核异常；目录项损坏也可能使文件名称失联或错误指向其他 inode。文件数据和普通 inode 即使仍在磁盘，也可能无法通过正常路径找到。在本章从磁盘加载 initproc 的启动流程中，根目录损坏还可能导致初始进程无法加载。

恢复需要备份、校验和、文件系统检查或日志等机制辅助，不能仅依靠现有目录遍历自动修复。日志与可靠文件系统属于本章选做内容，本次没有实现。

## 第七章问答

### 1. 管道的实际应用

例如统计一个文本文件的行数：

```sh
cat input.txt | wc -l
```

Shell 建立管道并创建两个进程，把 `cat` 的标准输出连接到管道写端，把 `wc` 的标准输入连接到读端。`cat` 顺序写出文件内容，`wc` 读取并统计换行符。进程关闭不需要的管道端点，写端全部关闭且缓冲区读完后，读取方得到 EOF。管道缓冲区满时写入等待、为空时读取等待，可以连接生产者与消费者，而不需要中间临时文件。

### 2. 更易用的多进程通信机制

可以设计由内核管理的邮箱或消息队列。进程创建邮箱获得句柄，使用 `send(destination, message)` 发送带长度与类型的消息，使用 `recv(mailbox, buffer)` 接收。多个发送者共享同一个接收队列，不需要为每一对进程单独建立管道，连接数量也不必随进程对数增长。

内核检查邮箱访问权限、目的端是否存在、消息大小和用户缓冲区，发送时复制消息或使用受控共享内存；同一队列可以保证 FIFO。接收方在空队列上阻塞，发送方在队列满时阻塞或返回可重试错误，并可选配超时与非阻塞模式。进程退出时释放邮箱、唤醒等待者并报告对端关闭；使用句柄代次或独立对象身份，避免 PID 或句柄复用造成消息误投。若要一对多通知，可进一步提供订阅主题与广播，但需明确每个接收者的队列容量和背压策略。
